# План: лендинг барбершопа Brass & Blade

Создан 23.10.2026. Проект для портфолио: бизнес вымышленный, адрес и телефон фиктивные.

## 1. Цель и критерии готовности

Одностраничный сайт барбершопа, который показывает работодателю или заказчику:
дизайн, адаптивную вёрстку, доступность, скорость, чистый код, тесты и CI/CD.

Проект готов, когда:

- сайт открывается на GitHub Pages, ссылка есть в README;
- Lighthouse (мобильный режим) — не ниже 95 по Performance, Accessibility, Best Practices и SEO;
- соблюдён WCAG 2.1 AA: контраст, работа с клавиатуры, видимый фокус, подписи полей, `prefers-reduced-motion`;
- вёрстка корректна на 360, 768, 1024 и 1440 px, горизонтальной прокрутки нет;
- e2e-тест формы записи проходит и на успешную запись, и на ошибки;
- в консоли нет ошибок, `astro check` чистый, CI зелёный;
- README содержит скриншоты, стек и описание решений.

## 3. Бренд и дизайн-система

**Название:** Brass & Blade — «латунь и лезвие», перекликается с латунным акцентом палитры.
Название на английском, весь остальной текст на русском.
**Тон текстов:** уверенный и короткий, на «вы», без канцелярита, с лёгкой иронией.

**Дизайн-система** описана в [docs/design-system.md](docs/design-system.md): палитра с проверкой
контраста, шрифты Oswald и Manrope, сетка, движение, компоненты `Button`, `Section`, `Badge`
и правила их использования. Поля формы (`Field`, чипы мастера и времени) делаем на этапе 4.

## 5. Форма онлайн-записи

Одна форма, поля идут по порядку:

1. **Услуга** — список с ценой и длительностью.
2. **Мастер** — карточки-чипы, есть вариант «Любой мастер».
3. **Дата** — `input type="date"`, от сегодня до +30 дней.
4. **Время** — слоты каждые 30 минут; последний заканчивается к закрытию (22:00) с учётом длительности
   услуги. Прошедшие слоты на сегодня
   недоступны. Часть слотов «занята» — детерминированно от даты и мастера, для реалистичности.
5. **Имя, телефон** (маска +7), комментарий по желанию.
6. **Согласие** на обработку персональных данных.

**Валидация:** своя, по общим правилам в `lib/booking.ts`, с понятными текстами ошибок. Ошибка выводится
под полем, связана через `aria-describedby`, у поля ставится `aria-invalid`, фокус переходит
на первое поле с ошибкой.

**Успех:** форма заменяется карточкой «Вы записаны: стрижка, Артём, 25 октября в 14:00».
Кнопку «Добавить в календарь» (`.ics`) решили не делать: для демо это лишний код.

**Честность:** рядом с кнопкой подпись «Это демо: заявка никуда не отправляется».
Сетевых запросов и хранения данных нет.

**Код:** логика (генерация слотов, нормализация и проверка телефона, текст подтверждения)
в чистых функциях `src/lib/booking.ts` и покрыта юнит-тестами.

## 6. Техническая часть

**Стек и инструменты:**

- Astro, актуальная стабильная версия, статическая сборка;
- Tailwind CSS v4 через `@tailwindcss/vite`, токены в `@theme`;
- TypeScript в строгом режиме;
- `astro:assets` (`<Picture>`) — AVIF/WebP, адаптивные размеры, ленивая загрузка;
- `@fontsource-variable/oswald`, `@fontsource-variable/manrope`;
- `@astrojs/sitemap`;
- Vitest — юнит-тесты, Playwright + `@axe-core/playwright` — e2e и доступность;
- Prettier с `prettier-plugin-astro`, `astro check`;
- GitHub Actions: проверка, тесты, сборка, деплой на Pages.

**Структура проекта:**

```
├─ .github/workflows/deploy.yml
├─ public/              favicon.svg, robots.txt, og.jpg
├─ src/
│  ├─ assets/images/    фото (оптимизирует Astro)
│  ├─ components/       Header, Hero, Features, Services, Masters, Gallery,
│  │                    Reviews, Booking, Faq, Contacts, Footer, MobileCta
│  │  └─ ui/            Button, Section, Badge (Field — на этапе 4)
│  ├─ data/             site.ts, services.ts, masters.ts, reviews.ts, faq.ts,
│  │                    copy.ts (тексты секций и формы)
│  ├─ lib/              booking.ts + booking.test.ts
│  ├─ layouts/          Base.astro (мета-теги, шрифты, JSON-LD)
│  ├─ pages/            index.astro
│  └─ styles/           global.css (Tailwind и токены)
├─ tests/e2e/           landing.spec.ts
├─ docs/               design-system.md, credits.md (источники фото)
└─ astro.config.mjs, package.json, README.md, PLAN.md, WORKLOG.md
```

Весь контент лежит в `src/data/*.ts`: чтобы поменять цены или мастеров, не нужно трогать вёрстку.

**SEO:** title и description, canonical, Open Graph и Twitter-карточка (`og.jpg` 1200×630),
JSON-LD `HairSalon` (адрес, часы, ценовой диапазон, рейтинг), sitemap, `robots.txt`,
favicon SVG и `apple-touch-icon`, `lang="ru"`, правильная иерархия заголовков.

**Бюджет производительности:** JS до 15 КБ в gzip, LCP до 2 с при мобильной эмуляции,
CLS до 0.05. Фото hero грузится с `fetchpriority="high"`.

**Фото:** бесплатные стоки с лицензией на свободное использование (Unsplash / Pexels),
около 15 снимков. Перед скачиванием покажу список, источники запишу в `docs/credits.md`.

## 8. Что сознательно не делаем

Бэкенд и реальную отправку заявок, CMS и админку, вторую языковую версию, блог и другие страницы,
онлайн-оплату, живой виджет Яндекс Карт (тяжёлый и ставит cookies), переключатель светлой темы
(сайт задуман тёмным), отдельную страницу-витрину компонентов. Любой пункт можно добавить
отдельным этапом.

## 9. Риски

- **Кириллица и пробелы в пути к папке.** Node и Vite обычно справляются. Если что-то сломается,
  предложу перенести проект в путь на латинице.
- **Название совпадёт с реальным барбершопом.** В подвале и README пометка «вымышленный бизнес»,
  телефон и адрес заведомо фиктивные.
- **Подпуть на GitHub Pages** (`/barbershop-landing/`). Задаю `base` в `astro.config.mjs`,
  все внутренние ссылки строю через `import.meta.env.BASE_URL`.
- **Лицензии на фото.** Только стоки со свободной лицензией, источники в `docs/credits.md`.
